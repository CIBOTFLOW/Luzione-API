# CONNECTOR-REVOCATION-L1-G0 working contract

Project: `CONNECTOR-REVOCATION-L1-G0` under controller `6ea70455e46b0f31b2b2ea94a42b3f51892d7ea9`, continued under controller `055cf5a5d277bead4b02146a05869d91712e5c91`, from exact API base `5786d9d6f1d38e730e404cade4dd466dbb709367`.

Outcome: publish one strict, default-off connector-revocation packet using the existing `ConnectorBinding/v1` meaning, API-owned P110 reservation/finality and an emulator-only provider boundary. `ConnectorRevocationRequest/v1` binds the same tenant, BOUND connector binding, provider account, versioned opaque credential handle, operation key, recomputed payload digest, deterministic emulator scenario and optional exact prior receipt. `ConnectorRevocationReceipt/v1` content-binds service and genuine-human authority, containment and normal kill versions, acknowledgement, source readback, remote finality, local credential disposition and recovery state.

Entrypoints are `POST /api/v1/connectors/revocations` and same-tenant `GET /api/v1/connectors/revocations/{receiptId}`. POST requires an authenticated service actor, a distinct signed human subject with the exact request or forward-recovery capability, global mutation admission, connector-revocation admission, exact tenant admission and the sandbox revocation destination. No client supplies tenant, service identity, human authority, kill version, receipt or finality.

Authoritative truth is the append-only tenant-scoped `connector_revocation_receipts` relation plus the linked P110 command/outbox/delivery/reconciliation evidence. Provider acknowledgement is pre-readback evidence only. `REVOKED` requires exact matching source readback. Local credential disposition remains `RETAINED` unless source-confirmed revocation or a distinct genuine-human forward-recovery append authorizes `ERASURE_AUTHORIZED_NO_EFFECT`. Forward recovery preserves the prior terminal non-success remote finality and cannot claim remote revocation.

The only registered implementation is `ConnectorRevocationEmulatorAdapter`, contract `luzione-provider-adapter/v0.3`, mode `SANDBOX`, effect class `NO_EFFECT`, destination `sandbox.connector-revocation` and binding `credential-binding:none:connector-revocation-emulator/v1`. It resolves no credential and performs no provider mutation. P110 reservation is tenant plus operation key; exact replay returns the original immutable readback and changed payload conflicts.

Mutation cone: two JSON schemas, strict parser and deterministic receipt issuer, POST/GET routes, append-only forced-RLS receipt relation, one emulator, P110 service integration, focused/adverse tests, disposable rollback/reapply proof and execution metadata. `ConnectorBinding/v1` and frozen Core tree bytes and meanings remain unchanged.

Acceptance: surplus/missing/wrong-version/digest rejection; service/human/tenant/binding/account/credential-version denial; active or unavailable normal/containment kill denial; exact replay and changed-payload conflict; ACK-versus-source-finality separation; unavailable, ambiguous, exhausted, version-mismatch and failed-revoke non-success; erasure-before-confirmation denial; genuine-human forward recovery without false remote finality; forced RLS, append-only update/delete denial, cross-tenant read denial, reverse-to-zero/reapply and full repository gates.

Non-scope: real credential access or erasure, live provider, hosted worker/poll, production database/query/migration, deployment/promotion, merge, default branch, activation, production rollback, G1/G2 or production readiness. Irreversible effects: none. Every exercised path is synthetic `NO_EFFECT`.
